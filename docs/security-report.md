### ค้าง / กำลังแก้
- กลาง: ส่งไฟล์แนบเป็นข้อความ JSON แล้วหลบตัวกรองลิงก์ไฟล์ได้ (กำลังแก้)
- กลาง: เครดิตงบกับเติมงบ PO เดียวกันพร้อมกันอาจคืนงบโดยไม่มีบันทึก (race แคบ — กำลังแก้)
- ต่ำ: อักขระควบคุมใน scheme ลิงก์, ลายเซ็นใน /api/signatures, pictureUrl (กำลังแก้)
- ผู้ใช้ต้องทำ: ย้าย `cloudflare/src` (สำเนา frontend เก่าที่ยังมีรหัสลัด) ไป archive — ระหว่างนี้ห้าม build/deploy จากโฟลเดอร์ `cloudflare/`

### ความเสี่ยงที่ยอมรับไว้ (ตรงกับระบบเดิม หรือผู้ใช้ตัดสินแล้ว)
- ไฟล์แนบเป็น anyone-with-link (ผู้ใช้เลือกให้เหมือนเดิม) — ใครได้ลิงก์ก็เปิดไฟล์นั้นได้
- ฝั่ง server ยังไม่บังคับ "เจ้าของเอกสาร" ในบางจุด (ระบบเดิมกรองที่หน้าจอเท่านั้น)
- ผู้ login แล้วเพิ่มรายการประวัติงบปลอมได้ (ไม่กระทบยอดเงินจริง)
- เปลี่ยนรหัสผ่านแล้ว token เดิมยังใช้ได้จนครบ 8 ชม. (ระงับบัญชีมีผลทันที)
- PBKDF2 100,000 รอบ (เพดานของ Cloudflare Workers) ชดเชยด้วยล็อก 5 ครั้ง/15 นาที

## 2. บั๊กการทำงานที่ prae-qa พบ (ไม่ใช่ช่องโหว่)
ตรวจ ~45 รอบ พบบั๊กประมาณ: สูง ~12 · กลาง ~35 · ต่ำ ~45 — แก้ครบทุกข้อระดับสูง/กลาง ส่วนต่ำแก้เกือบทั้งหมด ที่เหลือบันทึกใน tasks.md
ตัวอย่างระดับสูงที่แก้แล้ว: login โหมด Cloudflare ตกไปใช้รหัสในเครื่องเมื่อเน็ตล่ม, ข้อมูลหายตอนย้ายจาก Sheets (ยอดคืนงบ/สถานะปิดใช้งาน), ผู้อนุมัติตีกลับ PR ไม่ได้, ผู้ซื้อออนไลน์ปิดเคลมไม่ได้, แนบ PDF ใบเสนอราคาแล้วสร้าง PR ไม่ได้, เคลมคืนเงินแล้วยอดเครื่อง/server ไม่ตรงกัน

ผลเทสต์ล่าสุด: vitest 1164 ผ่าน · e2e Cloudflare local 9/9 ผ่าน

## 3. ระบบถูกแฮกได้ไหม
**ระบบใหม่ (Cloudflare) — ณ ตอนนี้ไม่พบช่องทางระดับวิกฤต/สูงที่เปิดอยู่**
- คนนอก (ไม่มีบัญชี): ทุก API ต้องมี token ที่ลงนาม, ไม่มีรหัส default/รหัสลัด, เดารหัสถูกจำกัด 5 ครั้ง/15 นาที, CORS จำกัดโดเมน, SQL ใช้ bind ทั้งหมด → ยังไม่พบทางเข้า
- คนใน (มีบัญชี): สิทธิ์ตรวจฝั่ง server ตาม role/level เดิม ช่องที่ใช้เพิ่มงบหรือแก้เอกสารข้ามสิทธิ์ถูกปิดแล้ว เหลือความเสี่ยงระดับกลาง/ต่ำตามหัวข้อ 1
- เงื่อนไข: ต้องตั้งค่าตามคู่มือ (`AUTH_TOKEN_SECRET` ≥32 ตัวอักษร, ไม่ตั้ง dev seed ใน production, Preview ไม่ใช้ D1 production, ไม่ deploy จาก `cloudflare/`)
- ยังไม่ได้ทำ (อัปเดต): `npm audit` ทำแล้ว — `npm audit --omit=dev` = 0 รายการ (ตอนติดตั้งเคยพบ 26 ช่องโหว่ใน dependency แต่ไม่ได้ใช้ตอน runtime) ; kla ตรวจรวมปิดเฟส 2 แล้ว (ดูหัวข้อ "เฟส 2 + M4") ; ยังไม่ได้ทดสอบกับ Google Drive จริง

**ระบบเดิม (GAS ที่ใช้งานอยู่ตอนนี้) — มีช่องโหว่ร้ายแรงที่ถูกแฮกได้**
- GAS เชื่อตัวตนผู้ใช้ที่ส่งมาจากหน้าเว็บ (ปลอมเป็นใครก็ได้ รวมถึง admin) และเดิมถ้าไม่ส่งผู้ใช้มาจะได้สิทธิ์ ADMIN
- รหัสผ่านเก็บเป็นข้อความธรรมดาใน Sheets และยอมรับรหัสกลาง 123456 / password123 / admin123
- ทีมแก้ default ADMIN ในโค้ด `gas/` แล้ว แต่ยังไม่ได้ `clasp push` (ต้องให้ผู้ใช้สั่ง) — ช่องโหว่อื่นจะหมดไปเมื่อย้ายไปใช้ Cloudflare
