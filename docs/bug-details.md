## ส่วนที่ 1 · ระดับวิกฤต

### C1 รหัสลัดเข้าเป็น admin ในชุดไฟล์ deploy เก่า ✅
- **ที่พบ:** `cloudflare/functions/api/[[route]].js` (สำเนา API เก่า) + `cloudflare/README.md` สั่งให้ deploy จากโฟลเดอร์นี้

## ส่วนที่ 2 · ระดับสูง

### H1 ผู้ใช้ตัวอย่างรหัส `password123` ใน schema เดิม ✅
- **ที่พบ:** `d1_schema.sql` (ทั้ง root และ `cloudflare/`) seed ผู้ใช้ 7 คนรวม admin level 99
- **อันตราย:** ถ้าใช้ไฟล์นี้สร้างฐานข้อมูล → login เป็น admin ได้ทันที
- **แก้:** ลบ INSERT users ออก (คงไฟล์ไว้ตามข้อกำหนด ติดป้าย DEPRECATED) และ login ปฏิเสธรหัส `123456`/`password123`/`admin123` เสมอ

### H2 บันทึกรายการงบในชื่อคนอื่น ✅
- **ที่พบ:** `POST /api/budget-transactions` รับชื่อผู้ทำรายการจากข้อมูลที่ส่งมา
- **อันตราย:** ปลอมประวัติการเงินในชื่อผู้บริหาร/ผู้อนุมัติ ตรวจสอบย้อนหลังไม่ได้
- **แก้:** ใช้ตัวตนจาก token เท่านั้น + บันทึก audit log ทุกครั้ง

### H3 เขียนทับ stock log ของคนอื่น ✅
- **ที่พบ:** `/api/stock/issue` ใช้ id ที่ส่งมาแล้ว `ON CONFLICT DO UPDATE`
- **อันตราย:** แก้จำนวน/ยอดคงเหลือในประวัติสต็อกย้อนหลัง ปกปิดการเบิกเกิน
- **แก้:** server สร้าง id เอง, ประวัติเป็นแบบเพิ่มได้อย่างเดียว (append-only), ตัดสต็อกแบบ atomic

### H4 เขียนทับรายการจัดสรรงบเดิม ✅
- **ที่พบ:** `/api/budgets/allocate` รับ id รายการเดิมแล้วแก้ยอด
- **อันตราย:** ผู้มีสิทธิ์งบแก้ยอดในประวัติย้อนหลัง
- **แก้:** append-only (`ON CONFLICT DO NOTHING`), id ใหม่สร้างฝั่ง server

### H5 รีเซ็ตสถานะ PR/PO ข้ามขั้น ✅
- **ที่พบ:** `POST /api/prs`, `/api/pos` ที่ไม่ส่งสถานะมา ใช้ค่าเริ่มต้นเขียนทับสถานะเดิม
- **อันตราย:** ดึง PR ที่ยกเลิก/อนุมัติแล้วกลับมาเป็น "ส่งแล้ว", ดึง PO ที่ยกเลิกกลับมาเป็น "สั่งซื้อแล้ว"
- **แก้:** ไม่ส่งสถานะ = คงเดิม ; ส่งมา = ตรวจการเปลี่ยนสถานะ (from→to) ตามสิทธิ์ทุกครั้ง

### H6 เติม/คืนงบไม่จำกัดยอด (L1 และผู้ซื้อออนไลน์) ✅ (ผู้ใช้ตัดสิน 2026-10-13)
- **ที่พบ:** `/api/budgets/adjust` แบบ TOP_UP / BUDGET_ROLLBACK และ `PUT /api/budgets/:dept`
- **อันตราย:** เพิ่มงบคงเหลือให้แผนกตัวเองได้ไม่จำกัด → ใช้งบเกินที่อนุมัติ
- **แก้:** ต้องอ้างเลข PO ที่มีจริง แผนกตรง ; ยอดคืนรวมต่อ PO ≤ ยอดที่ PO นั้นตัดงบจริง (ตรวจใน statement เดียว กัน race) ; ผู้มีสิทธิ์งบไม่ถูกจำกัด

### H7 ดันเพดานคืนงบด้วยรายการผูกพันปลอม ✅
- **ที่พบ:** ตอนปิด PO (settle) เพดานคืนงบคำนวณจากรายการ ledger ที่ผู้ใช้ส่งเองได้ และจากยอด PO ที่แก้ได้
- **อันตราย:** ผู้ใช้ L1 เพิ่มงบแผนกใดก็ได้ไม่จำกัด
- **แก้:** รายการผูกพัน (PR_COMMITMENT) server เขียนเองตอนอนุมัติ PR ; ยอดอนุมัติของ PO (approvedTotal) server คำนวณจาก PR ครั้งเดียว ; ตรวจแผนก

### H8 สร้าง PO ปลอมแล้วปิดเพื่อดึงงบ ✅
- **ที่พบ:** สร้าง PO ที่ไม่อ้าง PR จริง ตั้งยอดสูง แล้ว settle
- **อันตราย:** เพิ่มงบแผนกได้หลายล้านโดยไม่มีเอกสารจริง
- **แก้:** PO ใหม่ต้องอ้าง PR ที่อนุมัติแล้ว แผนกตรง ; ยอดอนุมัติไม่เกินยอด PR ที่เหลือ ; คืนงบได้เฉพาะ PO ที่มีรายการผูกพันจริง

### H9 แก้ยอด PR หลังส่ง แล้วดึงงบคืน ✅
- **ที่พบ:** แก้ `totalAmount`/รายการของ PR ได้ทุกสถานะ
- **อันตราย:** ปั่นยอดผูกพันให้สูง แล้วคืนงบเกินจริง ; แก้เอกสารที่อนุมัติแล้ว
- **แก้:** ล็อกยอด/รายการตามสถานะ (ร่าง = ทุกคน, ระหว่างตรวจ = level 2+, หลังอนุมัติ = ห้าม) ; ตรวจแผนกทุกการแก้ ; กัน id ชนกับเลขเอกสาร

### H10 คืนงบผ่าน BUDGET_ROLLBACK ไม่มีเพดาน ✅
- **อันตราย/แก้:** เหมือน H6 (ใช้เพดานเดียวกัน)

### H11 ใส่ `/` ท้าย path แล้วหลุดการตรวจสิทธิ์ ✅
- **ที่พบ:** กฎสิทธิ์รับ `/budgets/adjust/` แต่ตัวจัดการจับเป็นเส้นทางอื่น
- **อันตราย:** ผู้ใช้ L1 เขียนงบทุกแผนก
- **แก้:** normalize path ครั้งเดียวก่อนตรวจสิทธิ์และ routing ; ปฏิเสธ path แปลก (`//`, `%2f`, `%2e`, `%00`) ; กฎแบบตรงตัว

## ส่วนที่ 4 · ระดับต่ำ (สรุป)
แก้แล้วส่วนใหญ่ ได้แก่: วัดเวลาตอบเพื่อเดา username, id ชนกันใน ms เดียว, เลขเอกสารกระโดด, path decode ไม่ได้ตอบ 500, ข้อความ error ปน `[object Object]`, เดือน/ปีฝังในโค้ด, ชื่อไฟล์มีอักขระหลอกตา (bidi), เพดาน body เมื่อไม่มี Content-Length, ข้อความ legacy ในช่องลิงก์หาย ฯลฯ

ยอมรับไว้ ⚠️:
- เปลี่ยนรหัสแล้ว token เดิมใช้ได้จนครบ 8 ชม. (ระงับบัญชีมีผลทันที)
- PBKDF2 100,000 รอบ (เพดาน Workers) ชดเชยด้วยล็อก login
- ผู้ login แล้วเพิ่มรายการประวัติงบประเภททั่วไปได้ (ไม่กระทบยอดเงิน)
- ไฟล์กำพร้าใน Drive เมื่ออัปโหลดหลายไฟล์แล้วไฟล์หลังล้ม
- รูปเดโม SVG ของสินค้า 2 รหัสไม่ถูกเก็บในโหมด Cloudflare

แก้แล้วรอบล่าสุด ✅: อักขระควบคุมใน scheme ลิงก์, ลายเซ็นใน `/api/signatures`, `pictureUrl`, อ่าน body หลังตรวจสิทธิ์
ต่ำที่เหลือ (QA): items เป็นสตริงเสียกลายเป็น [] ตอน PUT, id ไฟล์แนบยาว ≥25 ตัวถูกตีเป็น Drive id, pictureUrl ต่างโดเมนเดิมถูกล้างเมื่อแก้ผู้ใช้ — client ปกติไม่เจอ

## ส่วนที่ 5 · ระบบ GAS เดิม (ใช้งานอยู่ตอนนี้)

## เฟส 2 + M4

ข้อมูล ณ 2026-10-13 · ตัวเลขรวมดูที่ `docs/security-report.md` (หัวข้อ "เฟส 2 + M4")

**ที่มา:** ก = ระบบเดิมก็มี · ข = โค้ดใหม่ของทีม · ค = เกิดจากการแก้ของทีมเอง

**บั๊กมาจากไหน:** ส่วนใหญ่เป็นช่องโหว่ที่ระบบเดิมมีอยู่แล้ว (ไม่ตรวจที่ server) ; บางส่วนอยู่ในโค้ดใหม่ของทีม ; บางส่วนเกิดจากการแก้ของทีมเองและจับได้ก่อนขึ้นใช้งานจริง

### ส่วนที่ 1 · ช่องโหว่ระดับสูง (kla-security) — แก้ครบ 4 ข้อ

#### P4 ปลอมชื่อ/ลบข้อมูลเคลม ✅
- **ระดับ:** สูง
- **อาการ:** ข้อมูลเคลม (claimData / storeClaims) รับเนื้อหาปลอมได้ โดยชื่อผู้แจ้งเดิมยังอยู่ ; ส่ง null ก็ลบเคลมได้ ; ส่งเป็น array จะข้ามการประทับชื่อ
- **อันตรายที่เกิดขึ้น:** เนื้อหาเคลมถูกแก้โดยคนที่ไม่มีสิทธิ์ ดูเหมือนคนอื่นเป็นคนแจ้ง หรือเคลมหายไป
- **วิธีแก้:** server รวมข้อมูลเอง, ประทับชื่อผู้แจ้งจาก token, กันคีย์สงวน
- **สถานะ:** ✅ แก้แล้ว
- **ที่มา:** ก

#### P5 เปิดไฟล์แผนกอื่นผ่านช่องหมายเหตุของ PR ✅
- **ระดับ:** สูง
- **อาการ:** ใส่รหัสไฟล์ของแผนกอื่นในช่องหมายเหตุของ PR ตัวเอง ระบบค้นข้อความทั้งก้อนแล้วให้สิทธิ์เปิดไฟล์นั้น
- **อันตรายที่เกิดขึ้น:** เปิดไฟล์ของแผนกอื่นได้ทั้งที่ไม่มีสิทธิ์
- **วิธีแก้:** นับเฉพาะช่องไฟล์แนบจริง
- **สถานะ:** ✅ แก้แล้ว
- **ที่มา:** ข

#### P5 เปิดไฟล์แผนกอื่นผ่านช่องลิงก์รูป ✅
- **ระดับ:** สูง
- **อาการ:** ตอนบันทึกไม่ตรวจเจ้าของไฟล์ แต่ตอนเปิดไฟล์นับลิงก์รูปเป็นไฟล์แนบ
- **อันตรายที่เกิดขึ้น:** เปิดไฟล์ของแผนกอื่นผ่านช่องลิงก์รูปได้
- **วิธีแก้:** ตัวดึงรหัสไฟล์ตัวเดียวทั้งสองฝั่ง + ผูกไฟล์กับเอกสาร + ตารางดัชนี file_refs (migration 0011)
- **สถานะ:** ✅ แก้แล้ว
- **ที่มา:** ข

#### P6 สร้าง PDF โหลดโค้ดจาก esm.sh ✅
- **ระดับ:** สูง
- **อาการ:** หน้าสร้าง PDF โหลดโค้ดจากเว็บภายนอก esm.sh
- **อันตรายที่เกิดขึ้น:** ถ้าเว็บนั้นถูกเจาะ โค้ดปลอมจะทำงานในหน้าระบบและขโมย session ได้

- **ที่มา:** ก
