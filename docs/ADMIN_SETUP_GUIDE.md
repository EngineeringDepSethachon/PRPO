## 2. สร้างแผนก / ฝ่าย (ต้องทำก่อนสร้างผู้ใช้)

เมนู **ข้อมูลระบบ** → แท็บ **แผนก / ฝ่าย** → ปุ่ม **เพิ่มแผนกใหม่**

| ช่อง | ใส่อะไร | ตัวอย่าง |
|---|---|---|
| รหัสย่อ (CODE) | ตัวอักษรอังกฤษสั้น ๆ ใช้เป็นเลขหน้าเอกสาร PR/PO | `PD`, `QC`, `PUR`, `MGT` |
| ชื่อแผนก / ฝ่าย | ชื่อไทยที่แสดงในระบบ | ฝ่ายผลิต |
| คำนำหน้า (PREFIX) | ปกติใส่เท่ารหัสย่อ | `PD` → เลข PR จะเป็น `PD001/2026` |
| ผู้จัดการ / หัวหน้าฝ่าย | ใส่ภายหลังได้ | — |
| สถานะ | เปิดใช้งาน | — |

ข้อแนะนำ: ตั้งรหัสแผนกให้คงที่ตั้งแต่แรก เพราะเลขเอกสารและรายงานงบอ้างอิงรหัสนี้ตลอด ห้ามเปลี่ยนภายหลัง

## 3. สร้างข้อมูลหลักอื่น (ทำก่อนให้คนเริ่มขอซื้อ)

ทั้งหมดอยู่ที่เมนู **ข้อมูลระบบ**

| แท็บ | ต้องมีเพื่อ | ช่องสำคัญ |
|---|---|---|
| **รายชื่อผู้ขาย / ร้านค้า** | PR แบบสั่งซื้อภายในต้องเลือกผู้ขาย (1 PR = 1 ผู้ขาย) | รหัสผู้ขาย (กดรันอัตโนมัติได้), ชื่อบริษัท, ผู้ติดต่อ, โทร, แผนกที่ใช้ (เลือก "ใช้ร่วมกันทุกแผนก" ถ้าไม่จำกัด) |
| **จุดจัดเก็บสินค้า** | ระบุว่าสินค้าเก็บที่ไหน (ไม่บังคับ) | ชื่อจุดเก็บ + แผนกที่ใช้ |
| **หน่วยเบิกใช้งาน / ห้อง** | เมนู "เบิกจ่ายด่วน" บังคับเลือกหน่วยเบิก ถ้าแผนกไหนไม่มีจะเบิกไม่ได้ | ชื่อหน่วย/ไลน์/ห้อง + แผนก |
| **แคตตาล็อกสินค้า** | รายการที่ให้ขอซื้อ/เบิกได้ | รหัสสินค้า (แนะนำพิมพ์เองเป็น `PD-001` แบบนี้ ปุ่มรันอัตโนมัติยังให้เลขเปล่า ๆ), ชื่อ, แผนก, หน่วยซื้อ/หน่วยนับสต็อก + อัตราแปลง, ราคาต่อหน่วย, จุดสั่งซื้อ (ROP), **สต็อกตั้งต้น** |

**สำคัญ:** ใส่ยอดสต็อกเริ่มต้นที่ช่อง "สต็อกตั้งต้น" ตอนสร้างสินค้าเท่านั้น เมนู "ปรับปรุงยอด" และ "รับเข้าคลัง (Manual)" ในหน้าคลังพัสดุ **ยังบันทึกไม่ลงฐาน** (บั๊ก S1 รอแก้) อย่าใช้จนกว่าจะแก้เสร็จ

## 4. บทบาท (Role) ที่ให้เลือกตอนสร้างผู้ใช้

| บทบาทในฟอร์ม | ทำอะไรได้ | ให้ใคร |
|---|---|---|
| **Requester – ผู้ขอซื้อ** | สร้าง PR ของแผนกตัวเอง, รับของ (GRN), เบิกจ่ายด่วน, ดูสต็อกแผนกตัวเอง | พนักงานทั่วไปของแผนก |
| **Reviewer – ผู้ตรวจทาน (Asst. Manager)** | ตรวจ PR ขั้นแรก (ผ่าน/ส่งกลับแก้ไข), จัดสรรงบประจำเดือน | หัวหน้าแผนก / ผู้ช่วยผู้จัดการ |
| **Approver – ผู้อนุมัติ (Plant Manager)** | อนุมัติขั้นสุดท้ายและออก PO, จัดสรรงบ, เห็นทุกแผนก | ผู้จัดการโรงงาน |
| **Purchaser – จัดซื้อออนไลน์** | รับงาน PR ช่องทางออนไลน์ (Shopee/Lazada) บันทึกราคาจริง/ร้านจริง | ฝ่ายจัดซื้อ |
| **Admin – ผู้ดูแลระบบ** | ทุกอย่าง + ข้อมูลระบบ + ผู้ใช้ + Audit Log | ผู้ดูแลระบบ 1-2 คน |

ลำดับงาน PR ปกติ: ผู้ขอซื้อส่ง → Reviewer ตรวจ → Approver อนุมัติ → ได้ PO → ผู้ขอซื้อรับของ
ดังนั้น **ต้องมี Reviewer และ Approver อย่างน้อยอย่างละ 1 คน** ไม่งั้น PR จะค้าง

## 5. สร้างผู้ใช้

เมนู **ข้อมูลระบบ** → แท็บ **ผู้ใช้งานและสิทธิ์** → ปุ่ม **เพิ่มผู้ใช้ใหม่**

| ช่อง | บังคับ | หมายเหตุ |
|---|---|---|
| รหัสพนักงาน | ไม่ | เช่น `EMP-PD-001` |
| ชื่อ-นามสกุล (จริง) | ใช่ | แสดงในเอกสาร/ไทม์ไลน์ |
| ชื่อแสดงในระบบ (Display Name) | **ใช่** (ฟอร์มจะไม่ให้บันทึกถ้าว่าง) | เช่น `คุณวิชัย (PD)` |
| ชื่อผู้ใช้ (Username) | ใช่ | อังกฤษตัวเล็ก ไม่มีช่องว่าง เช่น `wichai.pd` ใช้ login |
| ตำแหน่ง | ไม่ | — |
| สถานะ | ใช่ | เปิดใช้งาน ; เปลี่ยนเป็น "ระงับ" เมื่อลาออก (login ไม่ได้ทันที) |
| รหัสผ่าน | ใช่ | **รหัสชั่วคราว** ระบบเก็บเป็น hash และบังคับให้เขาตั้งใหม่ตอน login แรก |
| บทบาท | **ใช่** | ตามตารางข้อ 4 |
| แผนกที่รับผิดชอบ | **ใช่** | ผู้ขอซื้อ = แผนกตัวเอง ; Reviewer/Approver/Purchaser/Admin ที่ต้องเห็นทุกแผนก = "ทุกแผนก (ALL)" |
| ลายเซ็นดิจิทัล | ไม่ | วาดหรืออัปโหลด PNG/JPG ใช้พิมพ์บน PO |

กด **สร้างผู้ใช้ใหม่** ด้านล่างสุดของฟอร์ม

---

## 6. ส่งรหัสให้ผู้ใช้

ส่ง **แยกคนละข้อความทางช่องส่วนตัว** (LINE ส่วนตัว / โทรบอก) ห้ามโพสต์รวมในกลุ่ม ตัวอย่างข้อความ:

```
ระบบขอซื้อ/สต็อกใหม่: https://prpo-pdqc.pages.dev
ชื่อผู้ใช้: wichai.pd
รหัสชั่วคราว: (รหัสที่ตั้งให้)
เข้าครั้งแรกระบบจะให้ตั้งรหัสใหม่ของตัวเอง (6 ตัวขึ้นไป)
ใส่รหัสผิด 5 ครั้งจะล็อก 15 นาที / เข้าแล้วอยู่ได้ 8 ชั่วโมงแล้วต้อง login ใหม่
```

รหัสชั่วคราวใช้ได้ครั้งเดียว เพราะระบบบังคับเปลี่ยนทันที

## 7. จัดสรรงบประมาณประจำเดือน (ทำทุกต้นเดือน)

เมนู **งบประมาณ** → การ์ดแผนก → ปุ่ม **จัดสรรงบประมาณประจำเดือน (รหัสแผนก)** → ใส่จำนวนเงิน + หมายเหตุ → ยืนยัน

**ข้อจำกัดตอนนี้ (บั๊ก S2 รอแก้):** บัญชี Admin ยังกดจัดสรรไม่ได้ (เห็นข้อความ "รอการจัดสรรงบประมาณจาก Asst. Manager") ให้ใช้บัญชีบทบาท **Reviewer** หรือ **Approver** จัดสรรแทน (สร้างบัญชี Approver ให้ตัวเองอีกบัญชีก็ได้) ถ้าไม่จัดสรร PR ทุกใบจะติดธง "เกินงบ"

## 8. งานดูแลประจำ

| เรื่อง | ทำที่ |
|---|---|
| ผู้ใช้ลืมรหัส | ข้อมูลระบบ → ผู้ใช้งานและสิทธิ์ → แก้ไขคนนั้น → ใส่รหัสชั่วคราวใหม่ → บันทึก (token เก่าหลุดทันที บังคับตั้งใหม่ตอน login) |
| แอดมินลืมรหัส | ที่เครื่องแอดมิน ดับเบิลคลิก `reset-admin-password.bat` (ล้างคนอื่น: `reset-admin-password.bat ชื่อผู้ใช้`) ต้อง login wrangler อยู่ |
| พนักงานลาออก | แก้ไขผู้ใช้ → สถานะ "ระงับการใช้งาน" (ห้ามลบ เพราะเอกสารเก่าอ้างชื่อ) |
| ย้ายแผนก / เปลี่ยนบทบาท | แก้ไขผู้ใช้ → เปลี่ยนบทบาท/แผนก → บันทึก |
| ตรวจย้อนหลังว่าใครทำอะไร | เมนู **บันทึกระบบ (Audit Logs)** (เฉพาะ Admin) ปุ่ม "ล้างประวัติธุรกรรมจำลอง" ที่หน้านี้ **ไม่ต้องกด** (ของเก่าจากโหมดทดสอบ) |
| สำรองฐานข้อมูล | ที่เครื่องแอดมิน: `npx wrangler d1 export prpo-db --remote --output=C:\Users\Admin\prpo-backups\prpo-db-YYYYMMDD.sql` |
